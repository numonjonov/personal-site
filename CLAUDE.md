# numonjonov.com — портфолио

Личный сайт Pahlavon Numonjonov.

**С 10 ноября 2026 главная (`/`) — вариант v12**: тёмная пустыня из песчинок
на three.js, камера летит по скроллу, тексты глав в пространстве (раздел
«Вариант v12»). Корневой `index.html` — копия `v12/index.html` с SEO-тегами
главной (title, canonical, og, JSON-LD) и без `noindex`; стили и скрипт он
берёт из `/v12/` (`/v12/style.css`, `/v12/app.js`), так что правки кода
v12 сразу видны и на главной. **Правите разметку `v12/index.html` —
перенесите правку и в корневой `index.html`** (и наоборот), версии `?v=`
там тоже держите одинаковыми.

Прежняя главная — терминал — переехала в **`/v1/`** (`v1/index.html`,
`noindex`). Визуальный язык терминала: зелёный фосфор `#00ff41` на чёрном
`#0a0a0a`, один моноширинный шрифт (Courier New), рамки со свечением,
бинарное поле нулей и единиц на фоне, кастомный курсор, заголовки, которые
собираются из мусорных глифов. Референс по виду — `muhammad-ali.uz`; код
свой. Больше в терминальном стиле ничего нет: кейсы, резюме и 404 —
в стиле главной (ниже).

**Кейсы `work/*.html`, `resume.html` и `404.html` — в стиле главной (v12)**: общий
`v12/page.css` + `v12/page.js` (подключены абсолютными путями, `?v=2`; правите — поднимайте число во всех десяти файлах).
Тёмный лист `#151515`, IBM Plex Mono + Chakra Petch, сверху имя и
WORK / RÉSUMÉ / LET'S TALK (Telegram), справа линия прогресса чтения, внизу
«back to the desert». Фон — дюны из точек на 2D-canvas (своя проекция,
песчинки уходят вдаль по мере прокрутки, у курсора подсветка и воронка;
30 к/с, пауза в скрытой вкладке, при reduced motion — один кадр). Заголовки
`h1` и разделы `h2` расшифровываются из мусорных глифов (h2 — когда
появляются); перед печатью всё дописывается сразу. Номера разделов `01…` —
CSS-счётчик. `--ink` — RGB-тройка, на неё завязаны SVG-схемы кейсов.
Печать резюме — чёрным по белому (`@media print` в `page.css`).
Правки разметки шапки/подвала одинаковы во всех девяти файлах.

Чистые HTML, CSS и JS — **без сборки, без npm, без зависимостей**. Движения
написаны руками; библиотеки (three.js и др.) лежат в `vendor/`.

Публикация — GitHub Pages, домен в `CNAME` (`numonjonov.com`).

## Запуск

```bash
python3 -m http.server 4321
```

На Windows без Python — `powershell -File serve.ps1` (тот же порт 4321,
404-страница отдаётся как на GitHub Pages). Открыть `http://localhost:4321`.

## Версия на статике — не мелочь

Стили и скрипт подключаются как `styles.css?v=50` и `main.js?v=50`.
**Правите любой из этих двух файлов — поднимите число во всех HTML сразу:**

```bash
python3 - <<'EOF'
import pathlib, re
N = 51                                   # новая версия
for p in pathlib.Path('.').rglob('*.html'):
    if {'prototypes','lab'} & set(p.parts): continue
    s = p.read_text()
    p.write_text(re.sub(r'(styles\.css|main\.js)\?v=\d+', r'\1?v=%d' % N, s))
EOF
```

Без этого браузер и GitHub Pages ещё сутки отдают старый файл, и новая разметка
приезжает с прошлыми стилями — страница выглядит развалившейся.

## Варианты v2 — v5 (liquid glass)

Живут по адресам `/v2/` … `/v5/`, главная не трогается. Все четыре — один и
тот же контент (взят из терминальной главной, теперь `v1/index.html`), разный дизайн; у каждого свой
`style.css`, Google Fonts подключены тегом, JS-библиотек нет. Стоят
`noindex`, в `sitemap.xml` не входят. Внизу каждой — переключатель версий.

| | Направление | Шрифты |
|---|---|---|
| v2 | «лагуна»: CSS-сцена небо/море/песок, белое стекло, навигация-пилюля | Fraunces + Outfit |
| v3 | «pane»: тёмный дашборд, стеклянный сайдбар, bento-сетка | Plus Jakarta Sans + JetBrains Mono |
| v4 | светлая пастель, гигантская стеклянная типографика | Playfair Display + Figtree |
| v5 | тёмное «северное сияние», стеклянная линза за курсором | Unbounded + Onest |

Стекло везде одно: `backdrop-filter: blur() saturate()`, светлая кромка
`inset 0 1px 0`, блик через `::after`. Настоящее преломление (SVG-фильтр
`#lg` с `feDisplacementMap` внутри `backdrop-filter: url()`) объявлено
**второй строкой после обычного blur** — Chromium берёт его, Safari и Firefox
отбрасывают строку и остаются на blur. Так и задумано, не «чинить».

В кадрах `@keyframes` на стеклянных элементах нельзя анимировать `filter`:
Chrome на телефоне оставлял размытие после конца анимации (v2 на этом
попался).

доски.

- **Доски — `STATIONS` в `v7/app.js`:** центр на стене `c`, нормаль `n`.
  Капитан встаёт справа от доски (`stand`), лицом к зрителю, и показывает
  рукой на неё. Текст правится только в `v7/index.html` (`section.board`);
  `data-say` — реплика над головой, пока он идёт.
- **Кадр у доски — `framing`:** камера смотрит строго фронтально, а

  секция получает `left/top/width/height` и класс `show`. Раскладка внутри
  доски — container queries по её ширине (в конце `style.css`).
- **Узкий экран (< 760 px):** навигация — полоса снизу, раздел — нижний
  лист, капитан с доской — в верхней части кадра.
- Без WebGL — обычная страница: разделы друг под другом, навигация справа.
  `prefers-reduced-motion`: капитан и камера переносятся сразу, без ходьбы.

## Вариант v12 (пустыня а-ля aboutluca.com)

`/v12/` — **с 10 ноября 2026 это и главная `/`** (см. начало файла). По мотивам aboutluca.com: тёмная пустыня из песчинок, камера
летит над дюнами по скроллу, тексты глав висят в пространстве. Владелец
просил, чтобы эффекты были настоящими, а не снятыми «снаружи», — поэтому
всё сцена на своих шейдерах, без готовых постэффектов three.js. Шрифты
IBM Plex Mono + Chakra Petch (italic 600).

- **Рельеф** — `terrain(x, z)` в `v12/app.js` (value noise + fbm: гребни
  дюн, холмы, мелочь, долина вдоль пути). Путь камеры — `CatmullRomCurve3`
  по точкам над самым высоким песком рядом; их высоты сглаживаются только
  вверх (ложбины заполняются), иначе камера ныряет между дюнами и взгляд
  дёргается — так лагал переход LOG → LET'S TALK. `camAt(t)` растягивает
  скролл 0…1 на путь 0…0.985 (без упора — иначе камера врезается в конец и
  встаёт за кадр), продлевает точку взгляда за конец пути по касательной и
  ограничивает наклон −9°…+3°. Покадровой «страховки над песком» в `camAt`
  нет намеренно: пробы попадали на острые гребни и давали тряску 1–1.4° на
  отдельных кадрах. После правок рельефа проверяйте выборкой `__v12.camAt`
  с шагом 0.0005: запас над песком в окрестности 3×3 м ≥ 0.9 м (сейчас
  1.0), поворот взгляда на шаг — сотые доли градуса.
- **Скролл** — критически демпфированная пружина (`W = 4.2`, шаг дробится
  до 1/120 с), не простое догоняние `cur += (target - cur) * k`: у
  догоняния скорость скачет на каждом щелчке колеса, полёт идёт толчками, а
  свечение и аберрация, завязанные на скорость, мигают.
- **Гамма — матовая серая, как у референса:** не белые искры на чёрном, а
  серые «пушинки» в сером воздухе. Песок — 115 000 точек (на тач 55 000)
  с `ShaderMaterial`: размер по перспективе (`uPixel`), каждая песчинка —
  четыре мягкие доли со своей раскладкой (`SAND_FS`), свет по нормали
  рельефа без бликов, пыль, боке у камеры, туман уходит в серое. Яркость
  песка — `uExposure`, размер — `uSize`; бликов и ободка нет намеренно.
  Раз в 6–14 с по небу пролетает метеор с пунктирным хвостом
  (`stepMeteor`, 56 точек). Курсор — «фонарик»
  (`orb`) на луче мыши и кратер в песке вокруг него: радиус рваный от
  simplex-шума (`SNOISE`), сила `uMouseF` поднимается при движении мыши и
  гаснет через 2.5 с покоя. На тач фонарика нет.
- **Постобработка своя:** bright pass → separable gaussian на 1/4 и 1/8
  (HalfFloat на WebGL2) → композит: серый воздух светлее к центру и над
  горизонтом, еле заметные вертикальные полосы в небе, мягкая виньетка,
  зерно, слабая хроматическая аберрация только на скорости скролла.

  или справа, `head`, `lines`). Каждая надпись — плоскость с canvas-
  текстурой на фиксированной сетке символов; шейдер `TEXT_FS` расшифровывает
  её по клеткам (перебор глифов, дрожь срезов, RGB-сдвиг) и кладёт под
  буквы тёмный ореол — смешивание premultiplied, чтобы строка читалась
  поверх ярких дюн. Ставятся в базис камеры в точке `t` (`mkText`), а
  `placeTexts(aspect)` на узком экране сдвигает блок к центру и уменьшает,
  пока он не влезет в горизонтальный угол обзора. Кроме таймера расшифровки

## Как устроены разделы

Все четыре раздела терминала (v1) лежат в `v1/index.html` внутри `<main>` как

прячет правило `.js main > [data-section]:not(.is-active)`. Переключение —

ищется внутри самой секции, а не по `[data-section="…"] …` от корня.

## Правила

- **Не добавляй сборщик, фреймворк и зависимости.** Отсутствие тулинга — цель.
  Нужна библиотека — положи файл в `vendor/` и подключи тегом.
- **Названия банковских систем (`iABS`, `MyID`, `e-key`) на сайте — можно.**
  Это продукты вендоров и публичный госсервис. Чего на сайте быть не должно:
  серийник токена, CN сертификата и ФИО владельца, а также что-либо из
  реальных выписок.
- **Цвет только через переменные.** В SVG кейсов — `rgb(var(--ink))` и
  `rgba(var(--ink), .6)` (и в `styles.css`, и в `v12/page.css`). Печать резюме переопределяет переменные на чёрное
  по белому; захардкоженный цвет не переживёт печать.
- **Scramble — только через `.scramble`.** Скрипт разбирает текст на спаны и
  кладёт рядом `.sr-only` с оригиналом, чтобы читалки видели слово, а не мусор.
  `data-loop` — бесконечный цикл (маркер `// END OF PAGE`).
- **Бинарный фон рисуется два раза в секунду**, не каждый кадр, из атласа
  двух символов — это дёшево. Не надо переводить его на `requestAnimationFrame`.
- **Курсор — только мышь.** На тач, при `prefers-reduced-motion` и после Tab
  он прячется и системный курсор возвращается.
- **Терминал печатает, пока в кадре.** IntersectionObserver ставит на паузу,
  когда блок уехал или вкладка скрыта.
- **Форма контакта без бэкенда.** Submit собирает `mailto:` и отдаёт почтовому
  клиенту; лог справа честно пишет, что произошло. Нужен настоящий приём —
  поставить воркер и заменить ветку в `main.js`, разметку трогать не надо.
- **`prefers-reduced-motion` выключает всё движение:** печать, scramble, фон,
  курсор, пульс рамок. Остаётся статичная страница. Проверяйте при правках.
- **Ничего не прячем в CSS до старта скрипта.** Класс `js` на `<html>` ставит
  сам `main.js`. Не отработает — страница читается целиком.

## Документация проектов — `numonjonov.com/<проект>`

`.md`-файлы репозиториев проектов читаются **из GitHub прямо в браузере**,
бэкенда нет. `numonjonov.com/sms-service` — список документов проекта,
`numonjonov.com/sms-service/SMS_OTP_UZ.md` — документ: оглавление слева,
якоря на заголовках (кириллица и узбекский в id сохраняются), таблицы,
подсветка кода (`plsql`/`oracle` → sql, `sh` → bash, `ps1` → powershell).

**Оформление — прежний дизайн сайта, монохромный «чертёж»** (коммит
`c2b9a5d` в истории): лист `--paper` и чернила `--ink`, Archivo Black и
Space Grotesk с Google Fonts, HUD-рамка в `mix-blend-mode: difference` с
линейкой и уголками, плёночное зерно, свой курсор, полоса прогресса.
Всё это живёт в `docs/docs.css` и `docs/docs.js` (функция `engine`),
стиль сайта (`v12/page.css`/`page.js`) на этих страницах не участвует —
поэтому их правки документацию не трогают, и наоборот. Плавного скролла
трансформом и инверсии листа здесь нет намеренно: документы длинные.
Кириллицы в Archivo Black нет, русские заголовки падают в Arial Black.

**Как это попадает на статический хостинг.** Папки `/sms-service/…` на
GitHub Pages нет, поэтому запрос приходит в `404.html`. В её `<head>` стоит
`docs/projects.js` и короткий загрузчик: если первый сегмент адреса совпал
со `slug` из конфига, он ставит `html[data-docs]`, выключает `v12/page.css`,
подключает `docs/docs.css` и прячет `<body>` до старта скрипта; в конце
страницы `v12/page.js` подключается только без `data-docs`, а `docs/docs.js`
строит тело страницы заново и подгружает `vendor/`. Без совпадения —
обычная 404 в стиле главной. Статус ответа при этом 404 —
для документации это не важно, но для ровного 200 у проекта может быть
заглушка `<slug>/index.html` (как `sms-service/index.html`): она обслуживает
только адрес списка, вложенные `/<slug>/<файл>.md` всё равно идут через 404.

**Новый проект = одна запись в `docs/projects.js`** (`slug`, `title`,
`description`, `repo`, `branch`, `exclude`, `featured`). Заглушка —
копия `sms-service/index.html` с другим `<title>`, по желанию.

**Ключ и правка.** Кнопка `key` в хлебных крошках принимает fine-grained
personal access token GitHub (права: Contents read или read & write,
Metadata read — только на нужные репозитории). Он лежит в `localStorage`
этого браузера (или в `sessionStorage`, если снять галку «remember»), уходит
только на `api.github.com`. Без ключа публичные репозитории читаются
анонимно (лимит 60 запросов в час), приватные — показывают «Private
repository». С ключом появляется `edit`: textarea с живым предпросмотром,
`Ctrl+S` или `save` — коммит в ветку из конфига через Contents API
(`PUT /repos/{repo}/contents/{path}` с `sha`). Если файл в репозитории
успел измениться, GitHub отвечает 409/422: редактор подтягивает свежую
версию как базу, правки остаются в textarea. Несохранённый черновик
хранится в `localStorage` (`docs.draft.*`) и восстанавливается при
повторном открытии редактора.

**Кэш.** Дерево файлов — 3 минуты в `sessionStorage`, содержимое — по sha
блоба в `sessionStorage`, заголовок/описание для списка — по sha в
`localStorage`. Кнопка `reload` сбрасывает дерево.

**Версии.** `docs/projects.js`, `docs/docs.css` и `docs/docs.js`
подключаются с `?v=3` в `404.html` и в заглушках `<slug>/index.html`;
правите — поднимайте число там же (это отдельный счётчик, не `?v=` у
`styles.css`/`main.js`). Заглушка проекта — копия `sms-service/index.html`
с другим `<title>`: без `styles.css`, с `html[data-docs]`, шрифтами и
`docs.css` в `<head>`.
Отладка из консоли: `DOCS.render(md)`, `DOCS.meta(md)`.

Страницы документации — `noindex`, в `sitemap.xml` не входят.
