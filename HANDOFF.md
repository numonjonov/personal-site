### Как правильно вносить изменения дальше

1. Редактировать файлы **в `personal website v2`** — это рабочая копия.
2. Поднять версию ассетов во всех HTML (см. раздел в CLAUDE.md «Версия на
   статике» — сейчас `?v=41`, следующая правка → `?v=42` и так далее).
3. Синхронизировать в живой репозиторий:
   ```bash
   V1="/Users/numonjonov/Desktop/claude/personal website"
   V2="/Users/numonjonov/Desktop/claude/personal website v2"
   rsync -a --exclude='.git' --exclude='.idea' --exclude='.claude' --exclude='.DS_Store' "$V2"/ "$V1"/
   ```
4. Закоммитить и запушить **из `personal website`** (не из v2 — там нет git):
   ```bash
   cd "$V1" && git add -A && git commit -m "..." && git push origin main
   ```
5. GitHub Pages пересобирает сайт ~30–60 секунд после пуша. Проверить статус:
   ```bash
   gh api repos/numonjonov/personal-site/pages/builds/latest
   ```
   Смотреть на поле `status` — должно стать `built`.

Без пуша в `personal website` (v1-репозиторий) изменения **никогда** не
попадут на `numonjonov.com` — сколько бы правок ни было сделано в v2.
На это уже натыкались сегодня: правки час лежали только локально, пока не
разобрались, что живой домен вообще из другого места.
