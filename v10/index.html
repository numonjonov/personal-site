( About )

I'm a backend engineer at a commercial bank in Tashkent, working the layer between a core banking system on Oracle and everything that needs to reach it: REST services behind JWT, a wrapper around the state biometric identification provider, and digital-signature support inside a legacy JavaEE application.

The interesting problems are rarely the framework ones. They are the Oracle driver that breaks Cyrillic without the right encoding library, the vendor daemon whose annotations stopped matching its own API, the job queue that has to stay responsive on 256 MB of heap.

The layer between a core banking system and everything that needs to reach it: REST services behind JWT, a wrapper around the state biometric identification provider, digital-signature support inside a legacy JavaEE application, and PL/SQL packages where the logic belongs in the database.

Can you work with legacy systems?+

Most of what I write talks to something older than itself: Oracle, WebLogic, a provider without an SDK. The interesting problems there are rarely the framework ones — encodings, drifting vendor APIs, tight memory.

Why so few dependencies?+

Because every dependency is something to update at 3 a.m. The currency tracker runs on the standard library only — HTTP, the Telegram client and the chart renderer are hand-written.
